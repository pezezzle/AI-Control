# Architecture

AI Control has three separately maintained components: a platform-independent .NET core, a Windows WPF/WebView2 host, and a TypeScript/HTML/CSS frontend. The repository retains the working original WPF controller as an import baseline and a legacy source folder.

The shell loads only bundled assets from `https://ai-control.local`. Messages are accepted only from that exact HTTPS host and default port. The host recognizes a fixed set of commands; the frontend cannot submit shell commands. Install paths and model filenames are validated. The second WebView2 displays one configured loopback service and has web messaging disabled. ComfyUI and llama.cpp content cannot call the privileged shell bridge.

HTTP polling uses `/system_stats` and `/queue` for ComfyUI. llama.cpp uses `/health`, `/v1/models`, `/slots` and Prometheus `/metrics`. Both active and deferred jobs protect a normal stop. Unavailable or malformed workload data is unknown, never idle. Stop reads fresh status, then the PowerShell boundary verifies the configured executable and port owner before terminating that process. Stored startup PIDs are accompanied by their creation timestamp to protect against PID reuse.

Services start hidden, bind to loopback, and log outside Git. The app does not upgrade runtimes, install models or alter existing installation launch scripts. The llama.cpp launcher exposes metrics and slots, sets alias `local-coder`, uses a single request slot and automatic GPU fitting with a 1.5 GiB reserve for text or 4 GiB when loading a vision component. The extra reserve avoids exhausting Windows GPU memory when vision is loaded after fitting. Larger models may use system RAM with `GpuLayers=auto`. Image support can be saved directly on the coding server card; the host verifies fresh offline status and holds the operating guard while saving. Unknown status cannot change the launch configuration.

Only one service is started at a time through the host. It never automatically terminates the other service. Existing independently launched services are detected; unavailable identity or workload prevents silent termination. Scheduled stops belong to the open app and are canceled when the window is closed after confirmation. Servers remain running when the app closes normally.

Personal configuration is saved atomically under `%LOCALAPPDATA%/AIControl/settings.json`. Models are enumerated in the configured llama.cpp installation's `models` folder. Changing a model is permitted only while the coding server is offline. Installation and port settings require both servers to be stopped.

The editor action opens the selected project in VS Code. The built-in Assistant is a separate trusted-shell page backed by `AssistantChat`, not an embedded server page. Its native host calls the local completion API, assembles streamed responses and invokes a fixed set of workspace tools. The workspace implementation validates relative paths, linked paths, read/write permission and reviewed file versions. Model tool arguments cannot directly call arbitrary host bridge commands. PowerShell script execution is separately opt-in and requires full-content review; it is not a sandbox.

The global AGENTS.md is injected by the host before requests. An exact configured-path `read_file` call is routed through `AgentRules.Load`, retaining mandatory-file validation and reloading current contents. This exception is read-only and never authorizes arbitrary external files, directory listing, writes or script execution. The model is told to use injected rules without rereading them.

Global and scoped AGENTS.md rules are loaded by host code. Local speech recording is encoded as bounded mono PCM WAV in the trusted UI, then processed by a configured whisper.cpp CLI on the CPU. Transcripts return to the composer without submission. Image attachments are signature-checked and submitted only when the running server reports vision support. Matching projectors are loaded at server startup from `models/vision`. Context validation reads GGUF metadata; optional Continue synchronization edits only matching loopback entries in an existing JSON configuration.

## Persistent sessions and working context

`ChatSessionStore` uses GUID filenames, validates restored messages/tool pairings and writes atomically with flushed temporary files. Unreadable sessions are preserved and reported. Each `SessionRuntime` owns an `AssistantChat`; one host queue serializes generations and compactions. Every stream, approval, cancellation and dictation result carries a session identity. The host verifies both the active review identity and session before accepting approval. Interrupted tasks are not resumed.

The visible transcript is separate from the model's working memory. Checkpoints retain pre-compaction protocol messages and images. Summary requests use no tools; the host never executes restored tool calls. Fresh rules and current access remain authoritative. Context measurement uses llama.cpp `/props`, `/apply-template` and `/tokenize`; missing measurements block submission. `ResponseBudget` computes automatic output capacity as active capacity minus input and a 256-token margin before each inference/tool round. Custom output limits are clipped only to this available space. Missing legacy `AutomaticReplyBudget` properties default to true. An isolated context probe avoids changing active history while refreshing a count. Images have labeled estimated pre-request allowances, followed by the server's actual streamed usage when available.

Length-limited streams are read through their terminal event to preserve usage. Partial answers and reasoning remain in durable checkpoints. Incomplete tool calls are removed before history is saved and never executed. Model/tool rounds, successful in-task compactions and length recoveries have no fixed task-wide count limits. Automatic output resumes after successful compaction while partial answers or completed tools make progress; a repeated empty or identical partial answer after recovery ends as Incomplete. Successful tool results reset this comparison. Recovery disables thinking through the model template and keeps the exact current request and attachments. Custom output ends at its cap without implicit recovery; Manual/Off never compact implicitly. Full transcripts and pre-compaction checkpoints remain available. A truncated, malformed, empty or non-reducing summary rolls back instead of replacing working memory. Failed proactive compaction is skipped while usable output space remains, then retried when space runs out. Failed recovery or insufficient space ends explicitly with retained completed actions. Persistent progress and transcript round numbers accept nonnegative values without obsolete 16-round, 256-action or two-recovery bounds.

Rollback uses complete memory snapshots, rather than indexes into a history that compaction can replace. A host persistence callback saves each complete tool round before another inference. Cancellation during a multi-call proposal settles unanswered calls with explicit unexecuted/uncertain results and retains successful actions. Action receipts survive current-task compaction; they are untrusted results, never new approval. Storage failures stop further inference. Every later proposal still uses a fresh review identity. Rules are reloaded after compaction and before generation. Restart remains non-resuming.

The frontend renders a context status panel directly above the rounded composer. The transcript scrolls independently; model, access, attachment, dictation and Send controls stay in the composer toolbar. Single-line sidebar rows open a keyboard-accessible context menu targeting the clicked session independently of the selected conversation. Rename/delete dialogs retain that target; deletion preserves an unrelated selected chat. Completed answers use safe DOM-only Markdown rendering, with no HTML execution. `/context [show|hide]` is a local composer command, available through Enter or Ctrl+Enter while busy, with visibility stored in the local WebView profile. Per-session task progress carries the request, round, phase, completed tools, saved files, last action, recovery count and current thinking mode. Streamed answer entries retain their model round so switching chats cannot append a new round to an earlier answer. String builders and DOM text-node appends avoid copying a large answer on every token.

Host action receipts and recovery instructions use tagged user messages. They cannot become an assistant prefill or count as fresh user turns during compaction. Before measurement and inference, a cloned message list merges adjacent plain assistant messages from legacy history; original protocol history, checkpoints and content are preserved. This fixes strict templates rejecting two assistant messages at the end of a list. Tool-call boundaries are never merged. HTTP failures report endpoint/status and a bounded server cause, including malformed error-body handling.

Version 0.4.6 uses a native WPF Menu above both WebViews. Dark menu templates and DWM title-bar attributes keep the complete chrome dark. Menu commands dispatch a fixed menuAction to the trusted bundled UI; embedded service pages retain no privileged bridge. Clipboard text flows through the trusted host, while selection/undo/redo remain in the existing DOM. View preferences use WebView local storage and a validated viewPreferences command (75–150% zoom), leaving server configuration independent. Exit invokes the existing lifecycle protections.

WorkspaceAccess.WorkspaceWrite is a third per-chat file policy. Only complete write_file proposals bypass the review callback; run_script still requires its opt-in setting and separate approval. Workspace path/link/credential checks remain identical. WriteBackups stores exact previous bytes and metadata under LocalApplicationData before automatic overwrite; failure stops the write. Expected content is checked again immediately before replacement. The tool result records the retained previous version. Untouched generated global defaults migrate with a backup; customized instructions remain unchanged. No PC-wide mode or automatic script execution is added.
