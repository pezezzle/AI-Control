# Local assistant

Start the Coding server, then choose **Open in app** or **Assistant** in the sidebar. The assistant sends requests only to the configured loopback llama.cpp server. Chats and their full visible transcripts are saved locally under `%LOCALAPPDATA%\AIControl\chats`. **New chat** creates an independent session. Use the single-line sidebar titles to switch. Right-click a title (or press Shift+F10) for **Rename** or **Delete chat**. The menu targets that chat without switching the selected conversation. Deleted session files are retained for recovery; set their `deleted` flag to `false` while the app is closed to recover them. These JSON files contain conversation text, tool results, attached images and context checkpoints in plain text and stay outside the repository.

Choose the server's model on **Coding → Model for the next start**. A removed configured model appears as **Missing model**, and Start stays disabled until an installed model is explicitly selected. The selector never substitutes the first installed filename silently. A chat's desired model is independent; select the same model there before sending.

The rounded composer keeps attachment, access, context, model, dictation and Send controls in one row. Enter sends; Shift+Enter inserts a new line. Ctrl+Enter also sends. The gear beside the chat title opens workspace and instruction settings. Completed responses display headings, lists, tables and fenced code with a Copy button; streamed text remains plain until the round completes. Embedded HTML is displayed as text.

The native **File** menu provides New chat, workspace selection, folder/editor opening, Settings and Exit. **Edit** works with the existing input or text selection. **View** navigates sections and controls sidebar/context visibility and zoom from 75–150%; preferences are saved in the local WebView profile independently from server settings. **Help** contains Getting started, Keyboard shortcuts, backup/data folders and About. The menu stays visible on embedded service pages; native Edit is available in the bundled app interface. The title bar and menu popups use dark colors.

Ctrl+N creates a chat, Ctrl+Shift+O chooses a workspace, Ctrl+, opens Settings, Ctrl+B toggles the sidebar, Ctrl+Shift+K toggles context status, and Ctrl++ / Ctrl+− / Ctrl+0 change/reset zoom. Normal text-editing shortcuts keep working in the composer. Exit uses the same active-task and scheduled-stop handling as closing the window.

## Workspace and permissions

Choose a working folder through the gear beside the chat title. File tools use relative paths inside that folder. Absolute paths inside the same folder are normalized to relative paths and receive the same permission, link and credential checks. Paths outside the folder, ambiguous drive-relative paths, traversal, symbolic links, junctions, hard-linked files, device paths and alternate data streams are rejected. Credential files and common private/dependency directories are omitted. This is a bounded text workspace tool, not a general Windows security sandbox or a guarantee that every secret in an ordinary source file can be detected.

- **Read only** exposes listing, text reading and search.
- **Review writes** also allows file proposals. Every save requires review of the exact old and proposed content. A file changed after review cannot be silently overwritten.
- **Workspace write** creates and changes files in the selected folder and its subfolders without asking for each save. Path, link, credential and stale-content checks still apply. Previous versions are saved under `%LOCALAPPDATA%\AIControl\write-backups` with original bytes and metadata; a failed backup blocks overwriting. Activity identifies the backup. **Help → Open file backups** opens that folder. New files do not need backups. There is no deletion tool or PC-wide access mode.
- **Allow script proposals** permits requests to run existing PowerShell scripts. Each execution needs a separate approval showing the entire script. Scripts run as the Windows user and can access files or the network outside the workspace. This option is off by default. There is no automatic script execution or deletion tool.

Every session remembers its working folder, desired model and permissions. Choosing a different folder in a nonempty chat creates a new session to avoid mixing projects. Model and permission changes preserve the transcript, refresh mandatory rules and invalidate measured usage. Load the desired model on the Coding page before sending; the app rejects a mismatch instead of switching a running server automatically. Cancel interrupts inference and pending reviews; completed file changes remain saved. Tasks have no fixed model/tool round limit. A stopped task can be continued in the same chat using its retained working memory. Listing and search results are bounded; text reads and proposed files are limited to 128 KB. Only one assistant generation runs at a time. You can browse other chats, create a new one and queue a request there. Cancel applies to the selected chat; queued tasks also can be canceled. Tasks interrupted by app closure are marked interrupted on restart and are not replayed. Pending approvals never survive a restart.

Empty listing paths mean the workspace root; file operations still require a filename. Empty/excluded folders are reported explicitly. Activity entries identify the tool and supplied path, without logging proposed file content to a diagnostics file. During model reasoning, the interface shows measured reasoning-character counts and time for that response. Reaching the output budget marks the task **Incomplete** and retains its partial answer and working memory. If thinking used the entire budget, the activity explains that no final answer was returned. Unfinished tool proposals are discarded without execution. Already approved and completed file changes remain saved. These character counts are not token counts, and progress is not a guarantee that a model will complete a task.

## Instructions

`%LOCALAPPDATA%\AIControl\AGENTS.md` is the global rule file. The app creates a conservative default only when it does not exist. **Edit global AGENTS.md** opens it in the associated editor. It is loaded before every user request, regardless of the workspace. A missing global rule file blocks a request instead of continuing without it.

The model receives these contents directly and is instructed to use them without reading the file again. If it nevertheless calls `read_file` with the exact configured global rules path, the host reloads the mandatory rules and returns them without requiring a workspace change. This read-only exception grants no access to other files in AppData, directory listings, writes or script execution outside the workspace.

The workspace-root `AGENTS.md` is appended next. Before tools access a deeper path, `AGENTS.md` files along its directory hierarchy are added. New directory instructions are returned to the model before a write or script proposal proceeds. Rule changes are re-read on subsequent requests/operations. The selected workspace is the rule-discovery boundary; parent directories outside it are not read.

**Active instructions** lists the loaded paths. Global rules remain the baseline; narrower rules add project details. Rules guide the model, while host code enforces tool permissions and path checks independently.

## Images

Attach or paste up to four PNG, JPEG or WebP images, each up to 5 MB. The running model must support vision and be started with a matching `mmproj` component. Store that component at:

```text
<coding installation>/models/vision/<model filename without .gguf>.mmproj.gguf
```

Set **Image support** on the coding server card in **Overview** or **Coding** before starting. The choice is saved and locked while the server runs, loads or has an unknown state. Stop the server before changing it; toggling never interrupts a job or restarts the server automatically. The setting is also available in **Settings**. Turning it off starts without the vision component and uses less GPU memory. When a component is loaded, automatic GPU fitting reserves 4 GiB instead of 1.5 GiB to leave room for vision and working buffers. Explicit GPU layer counts still override automatic fitting. Model listing excludes the vision directory. The app checks the running server's reported modalities before submitting images. Visual recognition is not a guarantee of accurate OCR or interpretation. It analyzes images; image generation remains in ComfyUI.

## Dictation

Configure a local whisper.cpp CLI and a multilingual model in **Settings**. **Dictate** requests microphone permission, records up to two minutes, then **Stop recording** transcribes locally on the CPU. The transcript is inserted into the message field for review and is never submitted automatically. **Cancel transcription** stops the transcription process. Temporary WAV and transcript files are deleted after success, cancellation or failure.

No speech API, cloud account or token is needed. Microphone availability depends on Windows permissions and hardware. Model accuracy varies with language, background noise and recording quality.

## Context

Enter a custom context size between 2,048 and 1,048,576 tokens, or use a suggested value. The host checks the selected GGUF model's declared limit before startup. The runtime still decides whether memory allocation succeeds. Larger contexts can require RAM offloading and reduce speed. Settings apply after restarting the server.

Optional Continue synchronization updates only `local-coder` entries on a loopback API in the existing `~/.continue/config.json`, retaining a backup. YAML configurations are not rewritten automatically; Continue retains its own completion limits separately from the built-in assistant.

Under **Compaction settings → Output budget**, **Automatic · remaining context** is the default, including for saved chats from older versions. Before each model/tool round, the app allows the active capacity minus measured input and a 256-token safety margin. Input, internal thinking and final output share that capacity. For example, 258,048 active tokens with 8,000 input tokens permit up to 249,792 generated tokens. **Custom token limit** accepts 1–1,048,576 tokens, with 16,384 as the new-chat custom fallback; it is capped only by actual free context. There is no 8,192-token or half-context cap. Existing custom values are retained when an older chat migrates to Automatic. A model can end an answer sooner or impose its own runtime limits.

The context panel sits directly above the composer and shows remaining percentage, working-context tokens, active capacity and a progress bar. The small context ring and Close button also toggle it. Enter `/context` to toggle it, `/context show` to show it, or `/context hide` to hide it. These commands run locally without inference, preserve attachments, and remember visibility in the local WebView profile. Enter or Ctrl+Enter also executes a context command during a running response. Capacity comes from the running server's `/props`, not GPU utilization or the model's advertised maximum. `/apply-template` and `/tokenize` count text after applying the model's actual template, including current rules and tool definitions. Counts refresh before each request and tool round; final streamed server usage also includes generated output. While streaming, the panel retains the last measured count; reasoning-character progress is not a token estimate. For images, pre-request counts add an explicitly estimated 2,048-token allowance per attachment; the final server count includes actual image input when provided. Image estimates can differ from real use. An unavailable tokenizer leaves usage unknown and blocks inference instead of guessing. Template failures report the endpoint, HTTP status and server cause. Version 0.4.5 fixes an HTTP 400 caused by consecutive assistant action receipts in older working memory: outgoing copies are normalized for the server template while original history and checkpoints are retained. Refresh count repairs the measurement without replaying tools.

**Automatic** compaction runs before a new request and between completed model/tool rounds at 70% usage, or earlier if insufficient output space remains. Successful in-task compactions have no fixed count limit. **Manual** and **Off** disable implicit compaction and recovery; **Compact now** explicitly requests it. Older completed turns are summarized first, normally retaining the last two turns and their tool results. If the active task fills the context, its completed rounds can also be summarized; the current user request and attachments are retained verbatim, with host-retained receipts for completed write/script results. Manual compaction also supports a short conversation when there are no older turns. The same local model summarizes with tools and thinking disabled, using a separate short 2,048-token budget. This summary budget does not restrict normal answers. Current global/project rules are reloaded, summaries remain untrusted memory, and earlier approval never authorizes a new file action. Summaries can omit details; consult the full transcript when precision matters.

With both compaction and output budget set to **Automatic**, a length-limited response can save a durable checkpoint, compact, and resume the same task. Recovery has no fixed attempt count while partial answers or completed tools make progress. If a recovery again ends with an empty or identical partial answer and no successful tool result, automatic continuation stops as Incomplete to avoid repeating the same exhausted response. Recovery disables thinking for subsequent rounds and reports this in Activity and task progress. It never executes an incomplete tool proposal, replays stored calls, or grants approval to a new action. A **Custom** output limit ends a length-limited response without automatic recovery, even when compaction is Automatic; your selected limit is preserved. Failed recovery or insufficient usable context ends as Incomplete with the retained response and an explanation. You can correct the cause and continue in this chat; a new chat is not required by a round limit. There is no ability to pause and resume one model stream: recovery starts a new request at a validated boundary.

**Compaction settings → Thinking** controls `enable_thinking` for ordinary requests. It defaults to enabled for existing chats and depends on the model's chat-template support. Disable it when repeated reasoning consumes the output budget without producing an answer. This changes the template flag, not the output budget; there is no hidden reasoning-token or answer cap. Expandable task progress above the composer shows the latest request, model round, phase, elapsed reasoning/answer progress, completed tool count, saved-file count and last tool action. Internal thinking does not save files. File changes are saved only after a complete proposal and the selected access policy: approval in Review writes, or folder-limited preauthorization in Workspace write. A plain “continue” message uses retained working memory; it does not execute hidden or unfinished work.

Automatic compaction explicitly shows **Compacting previous context** before any summary output, with streamed summary-character counts and elapsed time for the current segment. The answer to the new message starts afterward; Cancel remains available. Summary generation disables thinking independently of the ordinary-request preference. A new queued/running request does not inherit a previous task's terminal status or completed-action counts. Summary characters and elapsed time show received progress, not an estimated completion time.

A successful compaction reports before/after counts and saves a durable checkpoint before replacing working context. Summary output uses the loaded model's measured remaining context, without a separate 2,048-token cap, and asks for a concise memory rather than reproduced code/logs. A truncated segment is discarded and retried with less source data; source position advances only after a complete summary. Empty, malformed or non-reducing summaries and canceled/failed compaction leave original working memory intact. If proactive compaction fails before a new message, Automatic reports the failure and still sends the message when the measured retained context has output space. It never bypasses actual capacity or checkpoint-storage failures. Complete tool rounds are persisted before further inference. Cancellation within a multi-tool round retains completed results and marks the remaining proposals as unexecuted or uncertain, rather than losing successful file changes from memory. The visible transcript, attachments and checkpoints are retained. **Context checkpoints → Restore** reinstates earlier working memory and retains a checkpoint of the current state; it never undoes file changes or replays tools. Compaction occurs between model requests, not during a stream. Manual/Off users must compact explicitly or start a new chat if input fills the context.

Response data and stored message text have a 32-million-character guard; session files are limited to 128 MB each. A storage failure stops further inference and is reported; old on-disk data is never silently truncated. Unsent composer drafts are isolated per session while the app is open, but are not persisted on restart. Automatic compaction and recovery are in-app features; they do not require a scheduled automation. Restart never resumes an interrupted task or approval.

Version 0.4.6 migrates only the untouched generated global AGENTS.md defaults to explain Workspace write authorization, retaining the old file as AGENTS.md.before-workspace-write. User-customized rule files are preserved. Project and directory rules continue to apply.
